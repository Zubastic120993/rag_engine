## Metadata implementation trace
### File discovery and scope routing
- `rag_engine/ingest.py:_iter_docs()` discovers PDFs under the CE_Library root and Markdown only under `90_CE_Wiki/`.
- `rag_engine/config.py:collection_from_relpath()` calls `rag_engine/scope_rules.py:explain_path_assignment()` to derive the `collection` field from relative path and `scopes.yaml` rules.
- `rag_engine/config.py:should_skip_dir()` excludes `.rag_db`, `.obsidian`, `30_Knowledge`, backup-like paths, and Graph folders from discovery.

### Document loading and text extraction
- PDFs are loaded by `PyPDFLoader`, which contributes loader metadata fields such as page data and document-info fields.
- Markdown is loaded by `TextLoader`; the project explicitly sets `page = 1` for Markdown documents.
- `rag_engine/text.py:normalize_text()` normalizes chunk text before persistence.

### Chunk creation and metadata construction
- `rag_engine/ingest.py:_embed_chunks()` assigns explicit chunk metadata fields:
  - `source`
  - `page`
  - `collection`
- Other PDF metadata survives from loader output because the project does not strip it before chunking.
- Chunk boundaries are created by `RecursiveCharacterTextSplitter` using configured `chunk_size` and `chunk_overlap`.

### Chroma insertion
- `rag_engine/ingest.py:_embed_chunks()` inserts chunk objects with metadata via `db.add_documents(chunk)`.
- Chroma IDs are generated by LangChain/Chroma at add time; the project does not define a stable chunk-ID scheme.

### Tracker/state persistence
- `rag_engine/ingest.py:_ingest_new_hash()` writes digest-keyed state into `embedded.json`:
  - `paths`
  - `chunk_ids`
  - `ingested_at`
  - `collection`
  - `extraction`

### Retrieval filtering and citation generation
- `rag_engine/query.py:retrieve_with_scores()` filters only on `collection`.
- `rag_engine/query.py:_sources_from_pairs()` exposes `path`, `page`, `collection`, and `distance` in answer sources.
- `rag_engine/pdf_links.py` builds safe local links from `source` and `page`.

### Fingerprint, events, and evaluation
- `rag_engine/fingerprint.py` writes build/runtime provenance fields:
  - `embed_model`
  - `llm_model`
  - `chunk_size`
  - `chunk_overlap`
  - `normalization`
- `rag_engine/events.py` records runtime ask-event fields:
  - `ts`
  - `question`
  - `scope`
  - `status`
  - `exit_code`
  - `n_sources`
- `rag_engine/eval_run.py` reads and writes evaluation metadata outside production Chroma.
